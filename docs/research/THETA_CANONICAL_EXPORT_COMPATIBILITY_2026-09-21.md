## A genuine defect this review found and repaired

`EventPitRecord.underlying` (`src/research/event-pit-toolkit.ts`) was typed as a non-nullable `string`. Codex's real export legitimately produces `ticker: null` for market-wide events (a Fed decision or a GDP release names no single symbol) -- the same limitation exists in Codex's OWN older `normalized-event-evidence.ts::NormalizedEventEvidence.underlying: string` (also non-nullable, and `normalizeEventEvidence` treats a missing `underlying` as `IDENTITY_INCOMPLETE`), so this is not unique to Claude's module. Repaired this session: `EventPitRecord.underlying` is now `string | null`, and `fromCanonicalEventExportRow` maps `ticker: null` to `underlying: null` directly -- never a fabricated placeholder symbol.

## Real-data access boundary (honest limitation)

This compatibility review, the repair, and the dedicated consumer (`event-pit-canonical-export-runner.ts`) were all built and tested against a **structural fixture** reconstructing the six real rows' documented scheduled/known dates and event kinds (from `docs/operations/THETA_R7_CRITICAL_EVIDENCE_2026-09-21.md`'s own summary table), NOT the actual captured artifact. The real file lives at `research_exports/canonical-events/<contentHash>-<canonicalSourceSha>.json` on whichever machine ran `tools/capture-canonical-event-export.ts`, that directory is gitignored, and capturing it requires a local worker identity/token (`.theta-local-worker/runtime.json`, `.theta-local-worker/worker.token`) this research branch's environment does not have. `CANONICAL_EVENT_EXPORT_CONSUMED = NO` for this reason -- not from lack of effort, but because the artifact and the credentials to fetch it both belong to Codex's Production/worker environment, not this research session. The conversion path is proven structurally sound; running it against the literal real file is the next concrete task once that file (or equivalent access) is available to this branch.
